    12. Web服务

    12.1. Introduction

    我们在上一章介绍了多个 TCP/IP 客户端-服务器应用程序。由于客户端和服务器之间交换的是文本行，因此它们可以使用任何语言编写。客户端只需了解服务器所期望的通信协议即可。

    Web服务同样属于TCP/IP服务器应用程序。它们具有以下特征：

    • 它们由Web服务器托管，其客户端-服务器通信协议是HTTP（HyperText传输协议），该协议构建在TCP-IP之上。
    • 无论提供何种服务，Web服务均采用标准交互协议。一个Web服务提供多种服务，如S1、S2、……、Sn。每项服务均需接收客户端提供的参数，并向客户端返回结果。对于每项服务，客户端需要了解：
      • 服务的确切名称（如果
      • 需提供的参数列表及其类型
      • 服务返回的结果类型

    一旦掌握了这些信息，无论调用哪个Web服务，客户端与服务器的交互都将遵循相同的格式。因此，客户端的编写得以标准化。

    • 出于防范互联网攻击的安全考虑，许多组织都拥有私有网络，且仅向互联网开放服务器上的特定端口：主要是Web服务的80端口。 所有其他端口均被锁定。因此，如前一章所述的客户端-服务器应用程序是在私有网络（内网）中构建的，通常无法从外部访问。将服务托管在Web服务器上，则使其对整个互联网社区开放。
    • Web服务可以被建模为一个远程对象。此时，所提供的服务便成为该对象的方法。客户端可以像访问本地对象一样访问该远程对象。这隐藏了所有的网络通信部分，并允许构建一个独立于该层的客户端。如果该层发生变化，客户端无需修改。
    • 与上一章介绍的 TCP/IP 客户端-服务器应用程序类似，客户端和服务器可以使用任何编程语言编写。它们通过文本行进行通信。这些文本行包含两部分：
      • HTTP协议所需的头部
      • 消息正文。对于服务器对客户端的响应，其格式为 XML（eXtensible 标记语言）。对于客户端向服务器的请求，消息正文可以有多种形式，其中包括 XML。 客户端的 XML 请求可能采用一种称为 SOAP（简单对象访问协议）的特殊格式。在这种情况下，服务器的响应也遵循 SOAP 格式。

    上述源代码是为托管该应用程序的 Web 服务器准备的。在生产环境中，该服务器通常是 IIS（Internet Information Server），即微软的 Web 服务器。Visual Web Developer 内置了一个轻量级 Web 服务器，用于开发模式。上述指令指示 Web 服务器：

    • 使用 C# 编写（属性 Language）
    • Web 服务的 C# 代码位于文件 [~/App_Code/Service.cs] 中（属性 CodeBehind）。Web 服务器将从该位置获取代码并进行编译。
    • 实现 Web 服务的类名为 Service（属性 Class）

    Visual Developer 生成的 Web 服务 C# 代码 [Service.cs] 如下：

    public Service () {

    public string HelloWorld() {

    }

    Service 类看起来像一个典型的 C# 类，但有几点需要注意：

    • 第 7 行：该类继承自定义在 System.Web.Services 命名空间中的 WebService 类。这种继承并非总是必需的。特别是在本示例中，可以省略它。
    • 第 3 行：类本身前面带有 [WebService(Namespace="http://tempuri.org/")] 属性，用于为 Web 服务指定命名空间。类供应商会为其类指定命名空间，以便赋予类一个唯一名称，从而避免与其他供应商可能使用相同名称的类发生冲突。对于 Web 服务，情况也是如此。 每个 Web 服务都必须通过一个唯一名称来标识，此处为 http://tempuri.org/。该名称可以是任意名称，并不一定必须采用 HTTP URI 的形式。
    • 第 15 行：方法 HelloWorld 前带有 [WebMethod] 属性，该属性告知编译器该方法应向 Web 服务的远程客户端公开。 未带此属性的方法对 Web 服务客户端不可见。这可能是被其他方法调用的内部方法，但不打算对外发布。
    • 第 9 行：Web 服务的构造函数。在我们的应用程序中，它没有用处。

    12.3. 一个算术运算 Web 服务

    我们将构建第二个客户端/服务器应用程序，其架构再次采用以下简化形式：

    前一个 Web 服务仅提供一个方法。现在我们考虑一个提供四则运算的 Web 服务：

    1. add(a,b)，返回 a+b
    2. 减法(a,b)，返回 a-b

    • 与 Global.asax 关联的类在应用程序启动时被实例化。其生命周期与整个应用程序一致。具体来说，它仅在 Web 服务器停止运行时才会消失。
    • 随后将执行 Application_Start 方法。这是该方法唯一一次被调用。因此，我们利用它来实例化所有用户共用的对象。这些对象被放置在：
      • 或者在与Global.asax关联的类的静态字段中。由于该类是永久存在的，因此任何用户的查询均可从中读取信息。
      • 或者是在 Application 容器中。该容器同样在应用程序启动时创建，其生命周期与应用程序一致。
        • 要将数据放入该容器，应编写：Application["clé"]=值;
        • 要读取该数据，则写入 T 值=(T)Application["clé"]; 其中 T 是 valeur 的类型。
    • 每当有新用户发起请求时，都会执行 Session_Start 方法。如何识别新用户？每个用户（通常是浏览器）在首次请求完成后，会收到一个会话令牌，该令牌是针对每个用户唯一的字符串。 随后，用户在每次发出新请求时都会返回收到的会话令牌。这使得Web服务器能够识别该用户。随着同一用户发出不同请求，其专属数据可存储在Session容器中：
      • 要将数据放入该容器，应写为 Session["clé"]=值;
      • 要检索该数据，则写入 T 值=(T)Session["clé"]; 其中 T 是 valeur 的类型。

    • 当 Web 应用程序未处理的异常上报至 Web 服务器时，将执行方法 Application_Error。
    • 其他方法则较少使用。
